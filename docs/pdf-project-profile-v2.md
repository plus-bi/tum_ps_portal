# PDF project profile extraction v2

> Superseded by v3 (multiple offers per document, retries and recorded failures, work modes and
> programming fields). See `pdf-project-profile-v3-plan.md`. This page describes v2 for history.

The v2 implementation lived in `backend/app/ingestion/project_profile.py`,
`llm_client.py`, and `profile_evidence.py`. It extracts one project profile from already stored
per-page Markdown. The LLM output is still experimental and is not written to the catalog.

## What changed

- Each list item has its own value and one or more page quotes. The v1 schema attached one
  evidence list to the whole field, so a list could contain unsupported individual claims.
- `project_goal` captures the intended outcome when the document does not name a formal
  deliverable. `methods_tools` retains named technology and methods for semantic matching.
  `eligible_study_fields` separates study program eligibility from skills, and
  `support_offered` separates coaching and feedback from learning outcomes.
- Field descriptions and the English prompt define the boundaries between project subjects,
  use cases, tasks, outputs, requirements, and learning. The prompt explicitly handles German
  and English source documents and keeps free-text values in the source language.
- `PdfTextCoverage` is computed from the extraction result, not generated by the model. It
  records blank Markdown pages and marks mixed or unreadable PDFs as partial or no text. A
  missing field in a partial PDF must not become a negative filter claim.
- `check_profile_evidence()` checks page ranges and quote presence after removing Markdown and
  HTML formatting. It returns review issues without logging document text. A passing quote
  check establishes source presence, not that the quoted text proves the normalized value.

The canonical result wrapper is `extract_project_profile_result_for_pdf()`: it includes the
profile, schema and prompt versions, prompt hash, model deployment, content hash, text coverage, and citation
issues. `extract_project_profile_for_pdf()` still returns only the profile for existing callers.
Profiles should be indexed or used as filters only after item-level review and any citation
issues are resolved.

## Language choice

Use one English instruction prompt for both German and English PDFs. The multilingual model
handled the German Project Study with German free-text values and `document_language="de"`
in the current sample. Working language remains an independently sourced project fact. A
separate language-classification call would add cost and a routing failure mode without a
measured gain. Reconsider separate prompts only after a fixed German/English evaluation set
shows better field accuracy or citation quality for the same schema and model.

## Small prompt comparison

The comparison used a German Project Study, an English technical IDP, and an English IDP with
an empty extracted second page. Seven Azure calls compared the original prompt with broader
and refined instructions. The broad prompt found more detail but invented deliverables from
tasks, moved mandatory PLC/Python skills under recommendations, and treated startup culture
as a learning opportunity. The refined prompt corrected those errors but pulled prerequisite
examples and a figure caption into subjects. Those failures informed v2's field descriptions.

Three v2 calls parsed successfully: the German sample yielded 26 sourced list items with one
quote issue caused by an inserted ellipsis; the English IDP yielded 20 items with no quote
issues; the mixed IDP yielded 31 items with no quote issues and `partial_text` coverage. This
sample is too small to establish catalog-wide accuracy. The prompt was then tightened to forbid
inserted ellipses; only the English technical IDP was called with that final wording. The scanned
PDF still needs OCR.

Use the fixed examples in `notebooks/pdf_markdown_samples.ipynb` for further prompt comparison.
Measure per-item factual precision and recall, required-versus-recommended classification,
page-quote validity, and handling of blank or scanned pages. Human review remains necessary
for semantic claims even when every excerpt appears on its cited page.
